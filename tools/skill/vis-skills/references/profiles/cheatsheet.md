# Animated cheatsheet format

Use this profile when the requested artifact is an all-at-once technical reference plate whose primary sections remain visible and independently readable. This is a format profile: combine it with the subject profile that owns algorithm, graphics, AI, or mathematical truth.

## Preserve the complete plate

At `t=0`, show the title, every primary section, its label, its principal example, and the complete reading structure. Do not begin from a blank canvas or serialize the sheet as slides. A local demonstration object may change or disappear when that behavior teaches the subject, but the section's identity and context remain visible.

Give every primary animated section a summary pose that communicates its point as a still. Author that pose as the initial state, depart from it during the local demonstration, and restore it before the loop ends. Static titles, captions, legends, proofs, and explanatory prose are allowed; a primary section may remain static only when inspection is the truthful interaction or the user explicitly requests it.

Animated cheatsheets default to `loop=true`, overriding the core one-shot default. At the exact final time, the complete sheet must again be useful. Prefer a final frame visually equivalent to `t=0`; never flash, erase information, or rely on an exporter's modulo behavior at the seam.

Several sections should remain active during ordinary playback. Stagger their high-salience peaks along the reading path, but do not make most sections wait for a row-major playlist. Extend the shared loop or reduce local repetitions before accelerating meaningful motion.

## Compose evidence modules

Each primary module has a concise subject claim or capability name, a concrete example readable at rest, one dominant recurring mechanism, a summary pose and return, and a short caption or observation. For API evidence, include the smallest recognizable verified call near the result it produces. For algorithms, use language-neutral pseudocode unless actual source code is the subject. Keep longer source context in the delivery integration rather than crowding the plate.

The module's operative verb must be visible: construction adds structure, comparison preserves aligned alternatives, mapping connects input to output, and verification tests a named invariant. Remove motion that only attracts attention. A cursor, travelling dot, pulse, underline, or camera sweep is valid only when it encodes a real operand or state.

Prefer a static editorial root with one completed child Scene per primary figure when modules need independent clocks, cameras, coordinate spaces, fields, or 3D views. Use Groups for modules that share one camera and clock. Preserve evidence geometry: mount child Scenes into aspect-matched Viewports and never use non-uniform scaling or shear to force a fit unless that transform is itself the subject.

## Layout, Theme, and visible text

When the user does not specify a visual direction, use built-in `pro_white` on every root and child Scene before creating objects. Use Theme typography and restrained neutral structure. Reserve accent color for one named semantic state or identity; preserve literal color when color itself is evidence. A host profile may explicitly override the Theme while retaining this sheet contract.

Choose one clear spatial topology—such as an atlas, aligned comparison, anatomy, trace, or process spine—from the content rather than decorating a generic card grid. Reserve disjoint regions for the header, each section title, evidence envelope, code or formula anchor, caption, and legend. Measure every animated module over its full cycle. Reflow, enlarge the canvas, or split the sheet before allowing unrelated regions to overlap.

Every visible string must teach the subject. Do not print production contracts such as loop status, clocks, figure counts, Theme, dimensions, FPS, engine, skill, audit, or review status. Omit decorative metadata and footers that do not state a useful subject fact. Preserve one concise title; add a subtitle only when it teaches something.

## Review

In addition to the core scene review, inspect `t=0`, each module's peak teaching state, representative concurrent-motion states, maximum density, worst text clearance, the exact final time, and both sides of the seam. Verify each module independently before mounting it, then verify the composed root. The final delivery should identify the subject profiles used, the module questions and loops, any intentionally static section, and any evidence or review that could not be verified.
